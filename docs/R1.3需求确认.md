# R1.3需求确认记录

记录日期：2026-10-26（北京时间）。本文件记录用户已明确的要求，**不是功能已实现或R1.3已发布的声明**。本次已实现并构建R1.3，验证边界见docs/验证报告.md。

## 名称、图标与界面

- 名称统一为“光路调度智能分析”，删除“纤路”和“离线光路初筛助手”品牌文字。
- 使用用户提供的橘红/橙黄折带几何原图作为桌面程序、窗口标题栏及品牌旁图标；不能用dy字母替代。搜索、导入、导出、交换和路线设施等功能图标保留原有深青/深灰语义样式。
- 四页导航统一在顶部：路由配置、中继段资源、节点类型、数据导入。
- 路由配置左置，方案结果右置；显示连接顺序和真实逐段资源；更多条件按需展开。“候选数量”改为“最多返回方案数”。
- 中继段资源按用户参考图组织统计、筛选、带端点类型和业务状态的宽表格，去除底部常驻中继段详情区。业务状态仅展示，不据此排除路由；零/缺失长度依旧按既有口径处理。
- 节点类型提供全部、光交箱、机房、光分纤箱、站点等带动态计数的一键筛选；保留节点类型修改、批量导入预览。多类型节点计数须说明可重复计入不同类别。
- 数据导入保持已确认的文件/工作表、自动编码、字段映射、预览和后台校验流程。
- 表格支持用户调整列宽、行高、列顺序和显隐；表格及详情区域分隔线可拖动，窗口变化时合理适配，保存个人布局并可恢复默认。不能将用户拖宽后的列重新强制压回固定宽度。

## 集群管理

- 放在节点类型页内的次级页签，不增加第五项主导航。
- 同一物理地址且有明确连通关系的设备可作为一个逻辑节点参与路由；不得仅凭同址、名称相似或-1后缀合并。
- 维护成员原始全名，保留真实资源边和并行中继段；资源更新不丢失已维护集群关系，未匹配成员列入报告。
- 连接顺序图保留两个实际成员，成员间虚线连接；**去掉“内部已打通”文字**。
- 内部虚线不额外增加实际中继段数、长度或跳纤次数。真实中继段仍须满足需求芯数；不得将无内部容量数据解释为已验证容量无限。
- 用户文件《集群管理.xlsx》包含695条记录，字段为设备名称、设备类型、集群类型、集群列表。读取时须处理工作表错误维度声明，不能仅按A1读取。
- 按成员列表归并，候选关系为299组多设备、65项单设备；1条设备名称不在其列表中，须核对。这些是分析统计，不能充当已完成导入或全量现场确认结果。

## 确认状态（用户最终口径）

节点类型和集群管理统一字段名“确认状态”，不再叫标注状态。

| 状态 | 规则 |
| --- | --- |
| 待确认 | 仅软件自动识别，没有对应表格提供的可用类型/关系，也未人工确认。 |
| 已确认 | 有对应表格成功匹配，或已经人工确认，且无明显异常。 |
| 需核对 | 有明显异常，需要用户再次核对，并显示具体原因。 |

仅由软件识别本身不构成异常，不能因此标需核对。异常优先于已确认。仅预览文件不算成功匹配并保存。来源与确认状态分开保存，保留旧数据迁移中无法反推来源的事实，不伪造来源。路由启用与确认状态独立：软件猜测的集群关系不能未经确认就参与合并。

## 数据存储及“离线”定义

- 用户的“离线”是脱离运营商内网运行，并非要求没有互联网；启动、查询和导入不能依赖运营商内网。
- 当前采用用户从本机选择表格、预览和校验后更新本地数据库的流程。云端＋本地方向保留，云端更新本轮暂缓，不部署更新服务。
- 本地数据库保存导入表格的结构化分析结果：中继段、节点、原始字段、连接索引、类型、集群及版本信息，不将原始Excel嵌入程序。
- 本机选表直接读取，不额外复制留存原表，不删除用户原文件。数据库、索引和可选备份仍占磁盘；数据目录允许选择，提供空间占用和必要清理入口。
- 未来若另行要求云端更新，须满足国内普通公网、无VPN依赖，并经用户实际网络验证；当前不声称已有可用云端服务。

## 本轮取消的更新功能

2026-10-26用户明确要求先删除复杂更新设计，后续有需要再提出优化。因此R1.3本轮不包含“更新中心”“数据更新/软件更新双页签”、自动云端更新及相关配置面板。对应两张设计图片已移出当前分支，不作为实现依据。

保留正常的数据导入、失败保留原库和资源回退；这与已取消的云端更新中心分开。旧版程序包未因本次文档修改而改变。

## 待实现与验证

保留上午确认的界面优化、名称及图标、集群管理、确认状态和表格自由调整要求。界面、确认状态、集群逻辑、原始格式兼容和全量数据预处理已实现，90项检查及全量黄金路径通过；Windows交互和高DPI尚未实测，必须继续保留此限制。图标目前是按参考图制作的矢量版本。

## 周期数据更新补充

用户补充需要长期反复更新。当前版本实现本机导入相同内容跳过、类型映射按变化写入、集群全量替换/补充选项（保留人工关系）、单份上一版资源库备份和最新导入异常报告轮替。原始表不打进程序、不重复留存。云端管理方统一发布＋客户端按版本拉取作为可行后续方案，需落实国内可访问的受控存储、权限与部署后再实现，不把该设想冒充已部署服务。
