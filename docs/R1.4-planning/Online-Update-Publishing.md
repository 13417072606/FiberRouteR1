# R1.4 管理方在线更新发布工具

客户端和命令行发布工具已实现。你尚未提供发布服务器，因此交付包不含活动的更新服务配置；两个检测按钮会明确显示“更新服务未配置”。签名、下载、校验及数据应用已使用隔离测试验证，国内公网部署仍需管理方提供地址后验证。

## 首次配置

准备一个国内可直连的 HTTPS 发布目录（同一域名，不依赖GitHub或VPN），例如 `https://updates.example.cn/fiber/`。此处是示例，不是实际服务。

在已安装R1.4的运行目录打开PowerShell。工具复用“程序”中的.NET运行库，无需额外安装SDK：

```powershell
& '.\程序\FiberRoute.Admin.exe' init 'D:\纤路发布工作区' 'https://updates.example.cn/fiber/'
```

会生成：

- `private-key.pem`：管理员签名私钥，离线保管、备份，不上传、不发客户。
- `client-config/update-service.json`：仅含HTTPS清单地址和公钥。发给客户，放到原运行目录 `资源/update-service.json`，重新打开设置即可生效。
- `site`：唯一需要上传服务器的目录。
- `release-payload.json`：本地维护两个渠道，不手工编辑服务器签名清单。

## 发布数据

先在管理方程序中导入、校验中继段表、节点类型、集群、机房归属。设置页“打开数据目录”可找到真实数据目录。以该目录为输入：

```powershell
& '.\程序\FiberRoute.Admin.exe' pack-data 'D:\管理数据' '2026-11-01.1' 'D:\发布包\数据-2026-11-01.1.zip'
& '.\程序\FiberRoute.Admin.exe' release 'D:\纤路发布工作区' data '2026-11-01.1' 'D:\发布包\数据-2026-11-01.1.zip' '更新中继段与节点归属'
```

发布包仅包含标准化 `resources.db`、去除个人设置与人工归属选择的 `catalog.db`、哈希清单；不携带源Excel、CSV或原始personal.db。完全相同的资源记录去重，真实不同的平行中继段保留。客户查看新增、变更、删除、无变化、元数据变化和人工冲突后确认应用。客户人工类型、个人集群、归属选择、目录及布局保留；冲突标需核对，集群和异常归属暂停归并。单条人工归属原来源被删除时也保留记录供核对。

当前数据通道传输一份整理后的完整快照，客户端按差异应用、无变化忽略；不是网络层的增量传输。更新包下载和预览临时目录会清理，原始文件不留存；本地保留最近一次数据库备份供恢复，不累计源文件。

## 发布软件

使用开发方提供的**新版本完整运行目录**，不要用客户已运行目录或只有补丁DLL的目录代替。版本必须与DLL一致，例如1.4.1：

```powershell
& '.\程序\FiberRoute.Admin.exe' pack-program 'D:\新版本\光路调度智能分析R1.4.1' '1.4.1' 'D:\发布包\软件-1.4.1.zip'
& '.\程序\FiberRoute.Admin.exe' release 'D:\纤路发布工作区' software '1.4.1' 'D:\发布包\软件-1.4.1.zip' '软件更新说明'
```

只打包程序、资源、许可、启动器和说明；不替换客户数据库、导出结果或人工记录。客户“检测软件更新”后，再点“下载并升级”，程序退出，由独立组件校验、备份、替换后重新启动；失败尝试回退。升级组件使用临时副本，避免自身文件锁定；下次启动清理旧临时副本。最近一次程序备份保存在本地应用数据目录。

## 上传与客户操作

1. 上传 `site/program/<版本>/` 或 `site/data/<版本>/` 中的ZIP，保持文件名及路径不变。确认普通国内网络能下载、字节数和SHA256一致。
2. **最后**上传 `site/manifest.json`，建议该文件关闭长期缓存或设置短缓存。软件与数据分别签名发布，发布一个渠道会保留另一个渠道。
3. 客户在设置中分别点击两个检测按钮。软件更新直接安装并重启；数据更新先预览差异，再确认应用。

签名使用RSA-PSS/SHA256，客户端校验清单签名、同源HTTPS、包大小、SHA256及内容清单。服务器只保存公开清单和包，永远不要上传私钥或管理方原数据库。

暂不建网站后台也可运行上述工具发布；以后可在管理后台调用相同命令，实现“上传→校验→预览→发布”。软件启动和本地查询不依赖在线检查。
