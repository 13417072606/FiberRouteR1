# 管理方发布与Cloudflare Pages试运行

原运行目录“管理方发布工具.exe”继续可用，无需重新创建签名私钥。工作目录保存私钥，公开站点只上传site子目录内的清单和版本包。

## 已知部署状态

用户截图显示Pages部署成功，地址为https://guangludiaodu.pages.dev/ 。该地址由用户控制；本次没有登录其账号、代为上传生产文件或建立活动客户配置。执行环境访问此域名被网络策略403拦截，不能把该错误归因于用户站点。

在关闭VPN的电脑和手机流量分别打开https://guangludiaodu.pages.dev/health.json，应看到status为ok。404说明文件路径需要调整；连接超时需要先解决国内可达性。

## 首次发布小型测试数据包

1. 在管理方EXE选择测试数据库目录并关闭使用该目录的客户端，生成唯一版本的数据包。
2. 配置服务时客户HTTPS地址填写https://guangludiaodu.pages.dev/ ，保存到固定本地管理工作目录；工具首次生成签名私钥，此后沿用同一份密钥。
3. 生成发布清单，点击打开待发布目录。先检查site中每个文件大小，Pages单文件上限25MiB。
4. Pages控制台手动建立新的生产部署，上传site目录内的完整站点内容，保持data/版本/ZIP或program/版本/ZIP等路径；不要套一层site目录。必须保留另一个渠道清单引用的文件。index.html和health.json可在本地site目录一并保留。Pages会整体部署，不能只上传manifest.json而丢掉ZIP。
5. 可在site根目录添加_headers文件，对/manifest.json设置Cache-Control: no-store，避免旧清单缓存。
6. 部署完成后在EXE点击验证外网清单，确认与本次签名发布一致。导出客户配置，将update-service.json放到测试客户端资源目录，重开客户端后检测、下载、预览和应用测试数据。

## 费用和单文件限制

只用Pages免费版的纯静态站点，不开通R2或付费Workers。免费政策及限制以Cloudflare控制台为准。本轮既不要求购买域名，也不配置任何账单服务。

R1.4.2累计补丁约7MiB，可作为手动下载文件放到Pages。但当前管理方EXE生成的软件在线更新包通常包含完整运行库，可能超过25MiB，不能直接上传。不能把手动补丁ZIP当作在线升级器的软件包。需要另行完成签名分卷协议、发布工具分卷和客户端合并校验适配，才可通过Pages发布大包。数据包同样先检查大小。

当前EXE“发布到服务器目录”用于本地/共享文件夹，不是Cloudflare上传按钮；本次试运行通过网页手动部署。

公开Pages文件不需登录，签名保证真实性而不提供加密或下载鉴权；先使用模拟数据。
