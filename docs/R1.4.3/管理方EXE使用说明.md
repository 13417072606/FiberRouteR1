# R1.4.3 管理与Cloudflare发布

先关闭主程序、管理方工具和图标工具，完整解压补丁安装包，双击“安装补丁.cmd”，选择原运行目录（含程序、数据）。不要解压内部patch.zip。成功后启动“光路调度路由查询.exe”，标题应为R1.4.3。旧快捷方式也能启动。

私有修复包附带“数据/集群站点修复基线.db”。首次启动自动补入现有数据目录，保留人工名单和暂停选择；“集群过滤报告.csv”位于当前数据目录。若仅使用公开代码补丁，依次重新导入光分纤箱、光交接箱类型表并确认，再导入集群管理表并确认，即可重建同样的站点关系。无需重新导入中继段。

1. 主程序关闭后打开“管理方发布工具.exe”。第1步选择“数据更新”，资源来源目录选设置页显示的当前数据目录，版本例如2026-10-28.143，生成更新包。每次内容变化使用新版本号。
2. 第2步继续使用已有管理工作目录F:\管线资源发布区，客户HTTPS地址https://guangludiaodu.pages.dev/，服务器发布目录留空。保存服务配置，保留原私钥，不新建另一套工作目录。点击“应用到本机客户端”可安装公开配置。
3. 第3步生成发布清单，打开待发布目录。超过24MiB自动生成.zip.001等分片，签名清单会列出它们；不要自行再次分卷、改名或解压。原大ZIP留在工作目录的packages中，公开site仅使用分片。
4. Cloudflare打开已有guangludiaodu项目，创建新的生产部署，将site里面全部内容上传，保留data/版本号/等相对目录。不要上传整个管理工作目录，不要多套一层site目录，也不要创建另一个项目。上传包括health.json、index.html、_headers、manifest.json及data/program下的分片。
5. 回到第4步点击“验证外网清单”。Cloudflare手动上传跳过“发布到服务器目录”，该按钮仅用于本地/共享服务器。再在客户端设置检测数据更新，下载、预览、确认应用。先在一台客户机试用。

客户首次都要手动升级至R1.4.3，并安装client-config/update-service.json到原运行目录的资源文件夹，之后才支持分片更新。配置只有公钥；private-key.pem一直保留在管理员工作目录，不能上传或交给客户。Cloudflare Pages静态网址能够被访问不等于已经发布签名更新；必须完成清单验证及客户端下载安装测试。

当前方案使用Pages静态免费托管，不需要公司服务器，不开通R2/付费Workers。每片24MiB低于Pages单文件25MiB限制。当前不支持断点续传，网络中断后可重试；本地软件正常使用不依赖更新站点在线。国内不同网络连通性仍需用户实测。
