# 继续配置在线更新

管理员使用最新 R1.4.4 运行目录准备软件与数据，客户已安装 R1.4.3 或以上即可支持分片在线更新。辅助工具复用现有程序中的 .NET 运行库，不需要另装开发环境。

1. 关闭主程序及管理方发布工具，运行 `Start-Online-Update.ps1`。选择原软件运行目录，复用原 `F:\管线资源发布区`；按提示选择设置页中的实际数据目录。
2. 工具生成标准数据包；尚无当前软件版本时，同时生成软件更新包。它保留已发布的同版本或更高软件版本，不重复覆盖；使用原签名密钥，超过 24 MiB 自动分片。工具安装到本机的只有辅助程序和公开客户端配置。
3. 输出中的“管理方数据”应符合预期的中继段及节点数量。成功后原工作目录中会生成 `待上传-版本号.zip`，内容直接包含 `manifest.json`、`data/`、`program/`，没有多套 `site` 文件夹。私钥、原始 personal.db、原始表及旧配置备份不在上传 ZIP 中。
4. 在现有 Cloudflare **guangludiaodu** 项目选择创建新部署 → **生产环境**，上传这个 ZIP 并部署。服务器发布目录继续留空，不必另外创建项目或购买服务器。Cloudflare 网页直接上传支持 ZIP 或文件夹，单个资产上限 25 MiB；本工具生成的分片为 24 MiB。[官方说明](https://developers.cloudflare.com/pages/get-started/direct-upload/)
5. 上传成功后再次运行 `Start-Online-Update.ps1 -Stage Verify`。这会使用原客户端配置访问真实地址，核对签名和本次发布清单，完整下载两个渠道的文件、合并分片并验证整体 SHA256，再验证软件文件及数据包。只校验，不替换客户程序或应用客户数据。
6. 完整验证通过后，在一台客户电脑放入原管理目录 `client-config/update-service.json` 到软件运行目录的 `资源` 文件夹。管理员本机的配置已由工具安装。客户在设置中检测软件/数据更新；软件升级后重启，数据更新需预览并确认应用。最后在真实客户机验收，才算整条链路完成。

缺少原签名配置、私钥，或路径不匹配时工具会停止；不会为现有站点另建签名密钥。请不要把私钥发到聊天或上传服务器。

本次发现旧软件发布器误把必需的 `System.Private.CoreLib.dll` 等运行库当作私钥，无法打包完整软件。源码已修正；辅助工具自身使用兼容的打包实现，因此管理员当前 R1.4.3/R1.4.4 不需先升级主程序即可使用辅助流程。此前已发布的 R1.4.4 安装包保持不变。

本聊天无法读取管理员电脑 F 盘，当前执行环境也无法访问该 Pages 地址；已完成的是隔离测试和工具准备。尚未替用户上传生产站点或在真实客户机安装，不把这些步骤表述为已完成。
