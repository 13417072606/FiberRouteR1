## 机房管理新一轮明确规则

- 机房归属不再从中继段始端/终端机房字段生成；中继段仅作为实际路由资源，原始字段可供来源核对，但不能建立或覆盖机房归属。
- 机房归属由五类设施表（光分纤箱、光交接箱、光终端盒、ODF、多媒体箱）中的明确“机房名称/所属机房”建立，不再沿用只纳入光交箱与机房类设施的限制；实际参与路由的成员仍须能匹配当前资源节点。相同真实机房中经过确认的设施视为一个逻辑整体，路由允许在成员之间通过机房内部尾纤跳通；实际中继段仍逐段核对长度、芯数和业务状态。内部跳通不伪造中继段、长度或可用芯数，需清晰标注其现场接续和容量尚待核验。
- 历史中继段归属须从路由图的归并入口排除；人工确认与暂停状态保留，但对应的设施表归属变化须提示复核。
- 用户此前提出“机房名称包含挂墙时，在导入时自动过滤删除”，具体过滤对象限于机房归属关系、保留设施与真实中继段；“壁挂”仍按原规则核对。这个过滤口径此前要求先答复再确认，尚待用户明确是否与新规则同时实施。
- 节点类型和机房归属页面默认左 76%、右 24% 的布局修改并入同批交付。

## 当前更新行为与待改进规则

- 当前手动导入中继段：相同文件内容加相同导入设置直接跳过；一旦内容变化，重新建立整张中继段资源库。新表没有的旧中继段会消失，不是只追加新增行。文件名不是资源身份依据。
- 当前手动导入设施类型表：精确名称匹配后新增或覆盖命中项，但未出现的旧类型记录通常不自动删除。机房归属按“类型表：文件名”这个来源键先删后插；同名文件会替换该来源，不同文件名会并存，可能形成旧归属冲突。来源证据同名文件按内容哈希跳过未变化输入，内容改变则替换该文件来源的旧证据。
- 当前手动导入集群表：默认勾选全量替换表格关系并保留人工维护；取消勾选可追加。建议把覆盖范围和删除预览写明，避免误操作。
- 当前在线数据更新：管理方发布的资源库为完整快照，客户端先预览新增、变更、删除，再以新快照替换中继段；类型、机房、证据、集群按发布包记录的来源范围同步，保留人工设置并将冲突列为核对。发布包内完全相同的中继段去重；客户端若比对无变化则不重复应用。来源名改变也可能影响元数据同步，不能把文件名当长期稳定身份。
- 建议下一轮将设施表身份改为“设施类别＋可配置的稳定来源标识”，与物理文件名分离；导入时比较内容哈希和规范化行键。完全相同跳过；新增行补充；同键内容变化更新并列出差异；缺失旧行仅在用户明确选择“此类别全量替换”或管理方发布完整快照时删除，其他文件和人工记录不随单张表缺失而删除。覆盖前显示新增、变更、删除数量及样例。

### 建议的统一更新契约

1. 数据分为四个独立范围：中继段资源、设施表节点类型、集群管理、机房管理。机房管理只取五类设施表的明确机房字段，不再读取中继段端点机房作为归属。更新一个范围不删除其他范围的原始数据。
2. 每张来源表注册稳定的“来源标识＋类别”，文件名和工作表名只作为显示及审计字段。首次导入新文件时明确其属于“已有来源的新版本”还是“新增来源”；同文件改名不制造第二份数据。
3. 每次先计算文件 SHA-256 与规范化行键差异。内容和导入映射完全相同则跳过；行键相同、字段不同则更新；新行插入；重复行折叠并报告重复数量；同键冲突或一设施多机房进入需核对，不猜测覆盖。
4. 手动导入提供“增量补充”和“全量替换所选来源”两种明确模式，默认增量补充。增量模式不因新文件缺行而删除旧行；全量模式仅删除所选来源中缺失的旧行，预览删除清单并保留回滚备份。中继段如果要更新全库，必须明确选择全量替换中继段资源；不能因仅导入一张设施表而删除中继段。
5. 在线数据包必须声明每个范围是完整快照还是增量包及其稳定来源标识。完整快照只同步被声明的范围；未声明的类别保持原状。客户端先验证签名、版本、文件哈希和行数，再显示新增／修改／删除数量，最后原子应用；失败回退。相同版本和哈希不重复写入。
6. 人工维护的节点类型、机房确认／暂停、集群关系独立保存。新官方数据与人工选择冲突时保留人工值、暂停有风险的逻辑跳通并列入复核；被删除的官方关系不应让旧人工选择自动恢复一条无来源的可路由关系。
7. 路由和报表只读取应用成功后的同一版本快照；任何类别变更后重新分析集群、机房及候选路由。预览提供变更清单、来源、行号、旧值和新值，并可导出复核表。

### ID 主键核查与更新口径

2026-10-29 最新更正：集群管理每次全量移除旧表格关系并重建；人工维护及历史人工确认是现有实现中的例外，具体含义见下文。机房管理的五类设施表均以 ID 为主键，按 `ODF＝光交接箱＞光分纤箱＞光终端盒＞多媒体箱` 认领；同类别同 ID、设施名称和机房等业务字段相同则跳过，业务字段变化则更新该 ID，**本次更新类别的新表未列出的旧 ID 删除**。文件名变化不改变 ID 身份；ODF 与光交接箱同级同 ID 冲突进入需核对。此前 R1.4.8 交付包已撤回，需以修正版重新封装。

本节以下口径按 2026-10-29 最新确认执行；上文“建议的统一更新契约”中的集群增量模式、机房按文件名长期识别等建议不再适用。

- 中继段手动导入和在线数据包都以本次完整表为最终范围：按业务 ID 比对，相同跳过、字段变化计为更新、新 ID 计为新增、旧 ID 缺失一律计为删除；实际资源库在校验后原子替换，以保持节点和中继段索引一致。重复或空 ID 拒绝导入。手动导入也显示新增、更新、删除数量。
- 集群管理每次手动导入或在线接收完整表格时，先移除旧的自动表格关系，再导入新关系；现有代码额外保留来源为“人工…”或“历史确认…”的本机记录。没有 ID 列不影响集群表全量替换。
- 机房管理以设施 ID 认领原始记录；同类别同 ID 的新行更新旧行，即使文件名改变也不保留两份。同一 ID 跨类别出现时，仅最高优先级类别参与机房归属，优先级为 `ODF＝光交接箱＞光分纤箱＞光终端盒＞多媒体箱`；同级多行不自动裁决，进入需核对，人工确认后才允许尾纤跳通。
- 机房设施表必须提供非空 ID；缺失 ID 的输入拒绝导入，不能用名称冒充更新主键。设施名称为空的记录保留 ID 原始行，但不参加机房归属或路由。不同 ID 但同名的设施，在中继段只有名称可匹配时进入需核对，不自动合并。
- 机房来源仍只取五类设施表明确的“机房名称／所属机房”；“挂墙”归属在导入时过滤，原设施和真实中继段不删除。同机房的已确认设施按原规则进行尾纤逻辑跳通。

- 用户最终明确中继段手动与在线均是完整覆盖，旧 ID 只要未在新表列出就删除。软件以 ID 对照生成差异，手动和在线使用同一对照函数；底层先生成并验证新资源库，再原子替换旧库，不逐行修改运行中的路由图。全量中继段快照 272,561 条有效记录的 ID 全部非空且唯一，此为数据核查结果。
- 集群管理每次以新导入表格全量替换旧表格关系，不依赖原始集群行 ID；人工维护记录按既有优先规则保留。原《集群管理.xlsx》无 ID 列，先前讨论的 5 条无法对应设施 ID 不构成集群全量更新的主键障碍。
- 五类设施原表合计 277,160 行，ID 全部非空且在五类表之间全局唯一；5 个完全相同的设施名称对应不同 ID（其中 4 组跨光分纤箱／光终端盒，1 组在光终端盒表内），另有 1 行 ID 非空但设施名称为空。详见 `docs/机房管理-设施同名不同ID及空名称复核.xlsx`。
- 因中继段端点仅提供设施名称，5 组同名不同 ID 都无法单凭名称将端点精确归给某一个设施 ID；其中 5 组均出现在当前资源节点，只有 1 组两条设施记录都填有相同机房名称。机房归属更新须以设施 ID 区分原始记录；同名多 ID 在无法区分端点时不能假定是同一物理设施，也不能伪造两设施之间的尾纤。空名称行保留审计，但不能参加名称匹配和机房路由。

### 提供用户复核的现行集群与机房规则

- 集群：原表完整成员名单优先；仅对真实分隔符拆分名称，括号内逗号和折行不拆散完整设施。纯光交箱名单达到两成员时直接成立，不受所属站点写法差异影响；一个光交箱加分纤箱时，按同一所属站点补齐；纯分纤箱按名单或一致站点归并。最终仍不足两成员的孤立项过滤。
- 集群确认：实际成员关系冲突、混合类型的所属站点冲突、人工集群重叠等进入需核对；名单成员没有独立设施行或暂无线缆端点仅作提示。已确认但可参与路由成员不足时为已暂停，不把路由不足混为需核对。纯光交箱至少两个成员有中继段端点；一光交加同站点分纤箱、纯分纤箱至少一个成员有端点；其余组合按至少两个成员判断。人工暂停优先。
- 机房：只读取五类设施表的明确“机房名称／所属机房”，不使用中继段端点机房、上联机房或站点名称。用设施 ID 跟踪同一设备的更新，再按精确机房名称把当前资源库中存在的成员归成整体。空值和“挂墙”不建立机房归属；同一设施 ID 对应多个不同机房值需核对，人工暂停或来源失效不得自动恢复路由。不同设施类别在同一机房可进行显式标注的尾纤跳通，真实段芯数仍逐段校核。
