# R1 更新发布协议

客户端默认不配置服务。本协议与模块已经实现；真实托管和客户端更新未验收。

1. 管理员离线保存RSA签名私钥（至少2048位）。仅将公钥PEM及HTTPS清单地址配置到客户端。
2. 资源包必须为UTF-8 CSV、长度米，使用标准中文字段；先在应用内导入校验，确认无非预期异常，再发布。程序包用 `scripts/package.sh` 生成的ZIP。
3. 程序版本使用可由 .NET `Version` 解析的版本号，例如1.0.1；发新版本前同步项目Version，客户端从程序集读取当前版本。资源版本为不重复字符串，例如2026-10-25。
4. 创建payload.json，属性名区分大小写：

```json
{"Program":{"Version":"1.0.1","Url":"https://example.com/FiberRouteR1-win-x64.zip","Sha256":"64位十六进制SHA256","Bytes":123},"Resources":{"Version":"2026-10-25","Url":"https://example.com/resources.csv","Sha256":"64位十六进制SHA256","Bytes":456}}
```

可将不更新的Program或Resources设为null。每个资源包Bytes必须精确，最多1 GiB；清单最多1 MiB。

5. 使用 `python3 scripts/sign-release.py payload.json private-key.pem manifest.json` 生成信封；签名为原始UTF-8 payload字节的RSA-PSS/SHA256（盐长度32）。信封包含base64 `payload` 和 `signature`。
6. 发布 manifest.json 和数据包到同一个HTTPS主机及端口，禁止重定向（包括对象存储/CDN跨域跳转）。不能要求交互登录。不要将运营商资源放到无授权公开地址；托管、访问控制与国内可用性需独立落实。当前模块不提供账号登录或长期凭据嵌入方案。
7. 客户端启动自动检查和下载资源；本地已有数据时，失败保留旧版。资源变动会清除路由结果并保留人工类型。程序包下载校验后，提示重启；复制更新助手及运行库到个人目录执行，等主程序退出再替换。备份位于个人目录program-backup-*。
8. 用真实Windows机器分别验证首装、断网、坏签名、坏哈希、取消、文件锁、程序替换、回退，再交付同事。程序更新助手会再次校验ZIP SHA256，限制写入范围，失败尝试回滚。

没有部署地址、凭据、实机验证时，不能宣称已完成自动同步。免费方案的额度与访问稳定性未作承诺。
