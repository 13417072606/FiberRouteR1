# R1 1.0.1 导入与布局修正版验证报告

构建日期：2026-10-25。环境：Debian 13 x64，.NET SDK 8.0.426，运行时8.0.32。目标：Windows x64，自包含 .NET 8 / Windows Forms / SQLite。构建与测试源码保存在 FiberRouteR1 仓库。

## 已验证

- Release 全解决方案编译通过，无警告或错误。
- 核心65项检查通过，包括交接文档 A–G、12段/20节点/1659.56米/40芯累计统计、24位ID与前导零保真。
- 需求芯数、跳纤上限、类型及具体节点规避、端点豁免、多标签、平行边、无解、取消、时间/扩展量/队列上限。
- 100个固定种子随机小多重图 × 4种排序，与完整枚举所有可行简单路径的指标前8名逐项对照，共400次对照通过。相同指标的内部顺序未作为保证。
- UTF-8、GBK、GB18030、带引号逗号与换行字段、非法记录隔离、米与千米转换、未知及零长度保留。
- 重复导入、导入中途取消后库文件哈希不变、校验失败原库保留、资源回退、人工类型及个人设置跨更新保留。
- 节点类型匹配预览、空类型、同名冲突、未匹配处理；预览不创建连接或更改原类型。
- RSA-PSS签名清单验证与篡改拒绝。
- Windows主程序、启动器、更新助手和SQLite DLL的PE x64标识；自包含运行配置、运行依赖及ZIP CRC检查由打包脚本自动验证。

## 本次新增验证

- 自动识别 UTF-8、GBK/GB18030、UTF-16LE/BE、UTF-32LE/BE（带BOM）并导入；编码检查覆盖采样区之后的字节，支持GB18030四字节字符。
- 分号及 Excel sep 行、制表符、带引号的逗号和多行字段、表头前后空白的预览/导入一致性。
- 不合法BOM编码拒绝，原数据库哈希保持不变。
- 实际生成的 XLS 和 XLSX 回归工作簿（各3工作表）：列出工作表、指定表导入、忽略Excel样式空列、长文本编号、纯零格式编号、千米换算和零长度。
- 两种工作簿的节点类型预览不修改数据、明确确认后修改；工作表缺失、错误表映射、取消时原数据库哈希不变。
- Release 编译包含顶部导航、统计卡片、条件栏、候选表、可滚动路径绘图控件及独立类型预览区域。仅确认编译，未把静态代码检查称为真实桌面布局验收。

## 合成规模测试

独立测试进程生成290,000行CSV，94,965,753字节，20,000节点，包含中文、长ID、辅助业务字段和平行边。

- 导入（包括SQLite写入、完整性检查、连接索引加载、数据库切换）：7,817 ms。
- 整个进程峰值工作集：169,619,456字节，约161.8 MiB，包括数据生成与完整导入。
- 高分支路径测试在队列上限10,000下10 ms退出，扩展732次，明确返回搜索受限；该用例只证明资源上限生效，不证明复杂大图能找到候选或最优解。
- 性能数值为此Linux机器单次结果，不能推定Windows电脑表现，也不能代替真实99 MB数据测试。

规模测试：`dotnet run --project tests/FiberRoute.Tests -c Release -- --benchmark`。

构建日志、测试日志及合成性能原始输出位于工作区 `artifacts/validation/`。

## 验证边界

编码自动识别按 BOM → 严格UTF-8 → GB18030 顺序选择；完全兼容多种编码的字节流无法唯一判定时仍允许人工指定。Excel 中原来就作为数值保存且被截断的长编号不能恢复，应在源表设为文本。真实用户报错CSV尚未上传，本次对仓库可复现的默认编码及表头一致性问题修正，并以合成文件/实际Excel格式测试；不声称验证了未提供的真实生产文件。
